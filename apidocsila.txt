1. SYSTEM ARCHITECTURE & ENVIRONMENT CONFIGURATION
================================================================================

1.1 Base URLs & Environments
----------------------------
- Local Development:
    http://127.0.0.1:8000/api/v1/
- Local Alternate/Legacy Mount:
    http://127.0.0.1:8000/api/
- Staging Environment:
    https://staging-api.ilaglobal.edu/api/v1/
- Production Environment:
    https://api.ilaglobal.edu/api/v1/

All endpoints in this specification are mounted under the `/api/v1/` prefix.

1.2 Global Request & Response Headers
-------------------------------------
- Content-Type: application/json (or multipart/form-data for resume/file uploads)
- Accept: application/json
- Authorization: Bearer <JWT_ACCESS_TOKEN> (Required for authenticated endpoints)
- X-Biometric-Token: <PIN> (Optional: Used for Level 1 master security gate override, default: "7890" or "ILA2026")

1.3 Authentication Protocol & Token Lifecycle (SimpleJWT)
---------------------------------------------------------
- Protocol: JSON Web Token (JWT) via rest_framework_simplejwt
- Access Token Lifetime: 60 minutes (Default, signed with HMAC-SHA256)
- Refresh Token Lifetime: 7 days
- Token Renewal: Send POST request to `/api/v1/auth/token/refresh/` with `{"refresh": "<token>"}` to receive a new access token.

1.4 Biometric Security Gate Token System
----------------------------------------
ILA Enterprise enforces an out-of-band biometric authentication header for sensitive Level 1 overrides (e.g. system administration, high-risk financial transfers, executive approvals).
- Header Name: `X-Biometric-Token`
- Accepted System PINs: Defined in settings (`BIOMETRIC_SECURITY_PIN`), default fallbacks `7890` or `ILA2026`.
- User State: If the user has `is_biometric_authorized=True`, the permission class `HasBiometricAuthorization` evaluates to `True` even without the header.

1.5 Multi-Tier RBAC & Permission Classes
----------------------------------------
The system classifies users into 8 distinct roles:
1. Super Admin: Full unconstrained system read/write access across all modules.
2. CEO / General Manager: Executive command, enterprise approvals, high-level reporting.
3. Department HOD (Head of Department): Department-scoped management, approvals, staff oversight.
4. HR Manager: HRMS, candidate hiring, payroll sync, employee records.
5. Marketing Exec: Marketing campaigns, leads analytics, outreach tracking.
6. Academic Counselor: Inquiry intake, course enrollments, student guidance.
7. Franchise Partner: Regional branch leads, sub-franchise analytics.
8. Student / Junior Consultant: Public course intake, gamified rewards, work-study applications.

Available Custom Permission Classes (`Applications.ILA_WEB.permissions`):
- `IsSuperAdminUser`: Checks `is_superuser=True` or `role == 'Super Admin'`.
- `IsCEOOrGM`: Checks `role in ['Super Admin', 'CEO', 'General Manager']`.
- `IsDepartmentHOD`: Checks `'HOD' in role` or executive/HR/marketing management roles.
- `HasBiometricAuthorization`: Validates `X-Biometric-Token` header or `is_biometric_authorized=True`.

1.6 Query Parameter Standards (Pagination, Filtering, Search, Ordering)
------------------------------------------------------------------------
All DRF ViewSets support standard query parameters:
- Search: `?search=<term>` (Performs case-insensitive containment lookup on designated fields)
- Ordering: `?ordering=<field>` (Ascending) or `?ordering=-<field>` (Descending)
- Filtering: `?<field>=<value>` (Provided by DjangoFilterBackend)
- Pagination: DRF PageNumberPagination (`?page=1&page_size=20`)

1.7 Standard Error Response Structures & HTTP Status Codes
----------------------------------------------------------
Success Codes:
- 200 OK: Successful retrieval or update
- 201 Created: Successful creation of a new entity
- 204 No Content: Successful deletion

Client Error Codes:
- 400 Bad Request: Validation failure or missing required fields
    {
      "field_name": ["This field is required."],
      "detail": "Descriptive validation message"
    }
- 401 Unauthorized: Missing, invalid, or expired JWT access token
    {
      "detail": "Given token not valid for any token type",
      "code": "token_not_valid",
      "messages": [{"token_class": "AccessToken", "token_type": "access", "message": "Token is invalid or expired"}]
    }
- 403 Forbidden: Authenticated user lacks permission to access or modify resource
    {
      "detail": "You do not have permission to perform this action."
    }
- 404 Not Found: Entity with specified ID does not exist
    {
      "detail": "Not found."
    }
- 429 Too Many Requests: Rate limit exceeded (e.g. 20 requests/minute on AI chat)
    {
      "detail": "Request was throttled. Expected available in XX seconds."
    }

3. LIVE AI CONSULTANT ("ILAS") & CONVERSATIONAL INTELLIGENCE
================================================================================

3.1 Architecture & Gemini LLM Pipeline
--------------------------------------
The Live AI Consultant module ("Ilas") provides automated, domain-aware advisory on:
- German language courses (Goethe/TELC A1 to C2)
- German Opportunity Card (Chancenkarte points, requirements, blocked funds)
- Study in Germany & University Admissions (APS, Expatrio, Coracle)
- Dual-vocational training (Ausbildung stipends and visa requirements)
- Post-arrival housing (WG Zimmer), Anmeldung, and part-time jobs

The backend utilizes Google Generative AI (`gemini-3.6-flash` / `gemini-1.5-flash`), with system instruction prompts grounded in ILA corporate standards, automated token audit logging (`AITokenUsageLog`), and smart fallback mechanisms for domain-specific queries if network or API limits are hit.

Rate Limiting: 20 requests per minute per IP address.

14.1 Production Axios Client (`src/services/apiClient.ts`)
----------------------------------------------------------
```typescript
import axios from 'axios';

const API_BASE = import.meta.env.VITE_API_BASE_URL || 'http://127.0.0.1:8000/api/v1';

export const apiClient = axios.create({
  baseURL: API_BASE,
  headers: {
    'Content-Type': 'application/json',
  },
});

// Attach JWT access token and biometric pin if available
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('ila_access_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  const biometricToken = localStorage.getItem('ila_biometric_token');
  if (biometricToken) {
    config.headers['X-Biometric-Token'] = biometricToken;
  }
  return config;
});

// Automatic token refresh interceptor
apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;
      const refresh = localStorage.getItem('ila_refresh_token');
      if (refresh) {
        try {
          const res = await axios.post(`${API_BASE}/auth/token/refresh/`, { refresh });
          const newAccess = res.data.access;
          localStorage.setItem('ila_access_token', newAccess);
          originalRequest.headers.Authorization = `Bearer ${newAccess}`;
          return apiClient(originalRequest);
        } catch (refreshErr) {
          localStorage.removeItem('ila_access_token');
          localStorage.removeItem('ila_refresh_token');
          window.location.href = '/login';
        }
      }
    }
    return Promise.reject(error);
  }
);
```

14.2 Custom React Hook for CRM Leads (`useInquiries.ts`)
--------------------------------------------------------
```typescript
import { useState, useEffect, useCallback } from 'react';
import { apiClient } from '../services/apiClient';
import { Inquiry } from '../types';

export function useInquiries(categoryFilter?: string) {
  const [inquiries, setInquiries] = useState<Inquiry[]>([]);
  const [loading, setLoading] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);

  const fetchInquiries = useCallback(async () => {
    setLoading(true);
    try {
      const params = categoryFilter ? { category: categoryFilter } : undefined;
      const res = await apiClient.get<Inquiry[]>('/inquiries/', { params });
      setInquiries(res.data);
      setError(null);
    } catch (err: any) {
      setError(err.response?.data?.detail || 'Failed to fetch inquiries.');
    } finally {
      setLoading(false);
    }
  }, [categoryFilter]);

  useEffect(() => {
    fetchInquiries();
  }, [fetchInquiries]);

  const submitInquiry = async (data: Partial<Inquiry>) => {
    const res = await apiClient.post<Inquiry>('/inquiries/', data);
    setInquiries((prev) => [res.data, ...prev]);
    return res.data;
  };

  return { inquiries, loading, error, refresh: fetchInquiries, submitInquiry };
}
```

15. ERROR CODES & PRODUCTION TROUBLESHOOTING RUNBOOK
================================================================================

1. HTTP 401: Token Not Valid / Signature Expired
   - Cause: JWT access token expired after 60 minutes or secret key modified.
   - Solution: Ensure the frontend interceptor dispatches POST `/api/v1/auth/token/refresh/` using stored `ila_refresh_token`.

2. HTTP 403: Forbidden / Permission Denied
   - Cause: User role does not possess permissions for this endpoint (e.g. Student role accessing `/staff/` or `/approvals/`).
   - Solution: Log in as Super Admin, CEO, or relevant HOD role. If Level 1 biometric check is active, include `X-Biometric-Token: 7890`.

3. HTTP 429: Throttled on AI Chat
   - Cause: More than 20 queries dispatched in 60 seconds from the same client IP address.
   - Solution: Throttling window resets after 60 seconds. On frontend, implement debouncing and disable chat send button while awaiting response.

4. HTTP 500: Gemini API Configuration Issue
   - Cause: Environment variable `GEMINI_API_KEY` missing or expired in `.env`.
   - Solution: The backend automatically falls back to domain-grounded knowledge templates so the user experience is never interrupted. To activate full LLM streaming, add a valid Gemini key to `.env` and restart the server.

25. FRONTEND INTEGRATION GUIDE (AXIOS & REACT)
--------------------------------------------------------------------------------

Frontend API Client Configuration:

  ```javascript
  import axios from 'axios';

  const API_BASE_URL = process.env.REACT_APP_API_URL || 'http://127.0.0.1:8000/api/v1';

  export const api = axios.create({
    baseURL: API_BASE_URL,
    headers: {
      'Content-Type': 'application/json',
    },
  });

  // Attach JWT Bearer token automatically
  api.interceptors.request.use((config) => {
    const token = localStorage.getItem('ila_access_token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  });

  // Example: Run AI Profile Matching
  export const matchStudyAbroadProfile = async (profileData) => {
    const response = await api.post('/study-abroad/profile-match/', profileData);
    return response.data;
  };

  // Example: Upload and Parse Resume
  export const uploadResume = async (file) => {
    const formData = new FormData();
    formData.append('file', file);
    const response = await api.post('/study-abroad/parse-resume/', formData, {
      headers: { 'Content-Type': 'multipart/form-data' },
    });
    return response.data;
  };

  // Example: Submit Lead Inquiry to CRM
  export const submitDepartmentInquiry = async (leadData) => {
    const response = await api.post('/intake/inquiries/', leadData);
    return response.data;
  };
  ```
